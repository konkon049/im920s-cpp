# IM920s コマンドと実機で確認した挙動

コマンドは「4文字のコマンド + (スペース + 引数) + CR+LF」。
ここに載せているのは読み出しと送信だけ。設定を書き換えるコマンド (`STxx`, `ENWR` など) は
フラッシュに書き込むので、このリポジトリでは使っていない。

## 読み出し

| コマンド | 内容 | 応答の例 |
|---|---|---|
| `RDID` | 固有ID | `000023B8` |
| `RDNN` | ノード番号 | `0002` |
| `RDGN` | グループ番号 | `000023B7` |
| `RDCH` | チャンネル | `16` |
| `RDRS` | 現在の受信強度 (RSSI) | `98` |
| `RDPO` | 送信出力 | `2` |
| `RDVR` | バージョン | `IM920s Ver.01.21` |
| `RPRM` | 全パラメータ | `ID:000023B8` `STNN:0002` … (複数行) |

存在しないコマンドには `NG` が返る。

## 送信

| コマンド | 内容 | 応答 |
|---|---|---|
| `TXDA 48454C4C4F` | 全員宛て (ブロードキャスト) に "HELLO" | `OK` |
| `TXDU 0001,4849` | ノード0001宛てに "HI"、相手の受信確認つき | 確認が返れば `OK` |

データは16進数で書く (初期設定 DCIO の場合)。

## 受信

受信すると次の形式の行が出力される。

```
00,0002,EE:48,45,4C,4C,4F
│  │    │  └ データ (16進数、カンマ区切り)
│  │    └ 受信強度 (RSSI、大きいほど強い)
│  └ 送信元ノード番号
└ (固定)
```

`TXDA` でも `TXDU` でも受信側の形式は同じ。

## 実機で確認した挙動

| 挙動 | 対応 |
|---|---|
| 33バイト以上を送ると `OK` を返しつつ**黙って32バイトに切り詰める** | 1回の送信は32バイトまで |
| 16進数の書式が崩れていても (奇数桁・16進数以外の文字) `OK` を返し、壊れたデータを送る | 送信側で正しい16進数を作る |
| 送信間隔が200ms未満だと約1割が `NG` | 200ms 以上あける / `NG` なら再送 |
| `TXDA` の応答は約20ms | — |
| `TXDU` (相手あり) の応答は約0.05〜0.6秒 | — |
| 存在しないノードへの `TXDU` は**約6秒後に `NG`**。その間は他のコマンドを受け付けない | 応答待ちは8秒程度。タイムアウトした応答は遅れて届くので取り違えに注意 |
| 2台が同時に `TXDA` で送るとお互い受信できない (20回中1回程度しか届かない) | 確実に届けたいときは `TXDU` |
| 2台が同時に `TXDU` で送っても、モジュールが自動で再送して全部届く (0.5〜2秒かかる) | — |
| コマンドは小文字でも受け付ける | — |
| コマンドの応答待ち中にも、受信データの行が割り込んで出力される | 受信行と応答を区別して読む |
