# ハードウェアの準備とトラブルシューティング

## 構成

```
PC ─USB─ IM920-USB (USB インターフェイスボード) ─ 変換アダプタ基板 ─ IM920s
```

| 項目 | 内容 |
|---|---|
| 無線モジュール | Interplan IM920s (Ver.01.21 で確認) |
| USB ボード | IM920-USB (旧型) / IM920-USB2 |
| 通信設定 | 19200bps, 8bit, パリティなし, ストップビット1, 改行は CR+LF |
| PC | Linux (Ubuntu で確認) |

USB ボードの USB チップは製造時期によって CP2102N または FT231X。
どちらも Linux ではドライバ不要で `/dev/ttyUSB0`, `/dev/ttyUSB1` … として認識される。

```bash
ls -l /dev/serial/by-id/     # どのポートがどのボードか確認
```

`/dev/ttyUSB*` を使うにはユーザーが `dialout` グループに入っている必要がある。

## 組み立て

IM920s はアダプタ基板に載っていて、アダプタ基板を USB ボードの**白い小型の基板対基板コネクタ**
(シルク「U2」の枠の右上) に差し込んでつなぐ。

- 向きを合わせて、コネクタどうしを**まっすぐ奥まで押し込む** (軽い手ごたえがある)
- そのあとでネジ止めする。ネジは固定用で、電気的な接続はコネクタだけ
- 本体の2列ピンヘッダ (U1) は旧型 IM920 用で、IM920s では使わない

## 動作確認

```bash
python3 -m serial.tools.miniterm -e --eol CRLF /dev/ttyUSB0 19200
```

`RDID` と入力して Enter → 8桁の ID (例 `000023B8`) が返れば OK。
終了は `Ctrl+]`。

## トラブルシューティング

### どのボーレートでも応答がない

アダプタ基板のコネクタが奥まで差さっていない可能性が高い。
白いスペーサーで浮いた状態でネジ止めされていると、見た目は固定されていても電気的につながっていない。
一度外して、コネクタを押し込み直す。

確認のポイント:
- PC からは USB ボード (USB チップ) しか見えないので、モジュールがつながっていなくても `/dev/ttyUSB*` は現れる
- 制御信号 (DTR/RTS)、フロー制御、ボーレートを変えても応答がないなら、ソフトではなくハードの問題

### さっきまで動いていたのに応答がない / 「使用中です」と出る

miniterm などが同じポートを開いたままになっている。開いたままだと応答を横取りされる。

```bash
fuser -v /dev/ttyUSB0 /dev/ttyUSB1    # 使っているプロセスを確認
```

miniterm は `Ctrl+]` で終了する。

### 送信は OK なのに受信側のデータが崩れる (例: `DE,DD,00`)

`TXDA` に文字をそのまま渡している。初期設定 (DCIO) では16進数で渡す必要がある。

```
TXDA HELLO          ← NG (崩れる)
TXDA 48454C4C4F     ← OK ("HELLO")
```

### 送信がときどき NG になる

送信間隔が短すぎる。200ms 以上あける。ライブラリ (`im920s.hpp`) は自動で間隔をあけて再送する。

### 受信できない

- 2台のチャンネル (`RDCH`) が同じか確認
- 2台が同時に `TXDA` で送るとお互い受信できない。確実に届けたいときは `TXDU` を使う
